# Screens

Mware Application Development Framework apps are single-page applications that contain either a single screen or multiple screens.

### Adding a screen

When adding a screen, you can either add a blank screen or add an autogenerated screen.

<figure><img src="https://files.readme.io/75bca971bfe92da77ceef6d1326cea1470b9b778e03939c88800e6c830125a5f-Screenshot_2024-08-23_at_14.57.43.png" alt=""><figcaption></figcaption></figure>

#### Blank screens

When adding a blank screen, you will be prompted to enter a path for the new screen.\
Capital letters and spaces are not allowed, however the modal will conveniently convert these to lowercase and hyphens if needed as you type.

#### Autogenerated screen

An autogenerated screen, is a screen generated from a table's data. Mware Application Development Frameworkis smart, it can read your data and generate tables and side panels for managing that data. When you add an autogenerated screen, it will add a screen with a single preset table .



**Adding autogenerated screens**

When adding an autogenerated screen, either a table or a form, you will be presented with options of the available data sources. Multiple sources can be selected at the same time. Once you have selected the data source(s) you will be presented with options for the type of form (for an autogenerated form screen), or how you would like to manage your rows (for an autogenerated table screen).

### Modal screen

A screen can be opened as a modal from linked [Table](https://docs.budibase.com/docs/table) rows, as well as from the [Navigate To](https://docs.budibase.com/docs/actions#navigate-to) action.

<figure><img src="https://files.readme.io/425b084-Screenshot_2022-06-15_at_14.10.32.png" alt=""><figcaption></figcaption></figure>

<figure><img src="https://files.readme.io/9ab19b8-open_modal.png" alt=""><figcaption></figcaption></figure>

Within the target screen you can use the **Close Screen Modal** [Action](https://docs.budibase.com/docs/actions) to close the modal and return you to the original screen.

### Access level

Screens are grouped and displayed by the chosen access level. If you have many screens, you can also use the search bar.

<figure><img src="https://files.readme.io/f4aa9666d8e8b4af3f6c4bbd24c022052a6b78cf9c7d2a606145f7af2b9e44f2-image.png" alt=""><figcaption></figcaption></figure>

\


The access level can be changed for any screen in the settings panel.\
App specific roles will determine if a user has the necessary permissions to see the screen.

<figure><img src="https://files.readme.io/0927a90-Screenshot_2023-06-29_at_15.58.07.png" alt=""><figcaption></figcaption></figure>

### On screen load

It is possible to fire Actions on load of the screen. Within the Settings Panel of the screen node, click the button beside _On screen load_ to add some actions.

<figure><img src="https://files.readme.io/921f7f1-Screenshot_2023-12-04_at_16.34.52.png" alt=""><figcaption></figcaption></figure>

Here you could do a variety of things such as a conditional redirect, Trigger an automation, or even set some initial App state.
