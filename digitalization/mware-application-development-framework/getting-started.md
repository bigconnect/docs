# Getting started

1. Create a new account&#x20;
2. Login
3. Step through the first app wizard, selecting the _Sample data_.

***

### Data

The column data types include a variety of options, including Text, Number, and Date/Time.&#x20;

Some fields are designated with special formatting to highlight their specific data type. For instance, fields like "Employee Level" may contain multiple selections, while fields like "Assigned" may reference linked records.

#### Autogenerated screens

To get started quickly, click on `Add screen`. Next select `Table` to create new CRUD (Create, Read, Update, Delete) screens for each of your tables.

These autogenerated CRUD screens will make use of the Table and Side panels for fast, all-in-one data interaction.

<figure><img src="https://files.readme.io/a60de79-Screenshot_2024-07-16_at_14.45.23.png" alt="Adding autogenerated screens"><figcaption><p>Adding autogenerated screens</p></figcaption></figure>

<figure><img src="https://files.readme.io/84242f9-auto_gen_screens.png" alt="Creating an auto screen for each table"><figcaption><p>Creating an auto screen for each table</p></figcaption></figure>

When creating screens you will be asked to provide an access level, but this can be changed later. This tutorial will use the default _Basic_ access.

<figure><img src="https://files.readme.io/3d3e656-Screenshot_2023-02-17_at_18.14.34.png" alt="Selecting new screen access level"><figcaption><p>Selecting new screen access level</p></figcaption></figure>

Click `Done` and a new screen will be generated for each table selected.

<figure><img src="https://files.readme.io/4c41cfa-Screenshot_2024-07-16_at_14.54.58.png" alt="Autogenerated screens"><figcaption><p>Autogenerated screens</p></figcaption></figure>

#### Components

With the screens created we can view and edit the components for each.

<figure><img src="https://files.readme.io/3ddc5d9-image.png" alt=""><figcaption></figcaption></figure>

With the Table component selected, you will be able to edit its settings via the Settings Panel. Here you can change the _Data Source_, _Filters_, _Sort Column_, and more. These settings are explained on the Table page.

You can also click `Add component` to add another component to your screen. You can view a list of available core Components and learn more about Data in design.

#### Blocks

In Mware Application Development Framework there is a category of components known as Blocks, which are collections of pre-built components designed to make building your apps easier and faster.

A list of them can be found in the _Blocks_ section of the components view.

<figure><img src="https://files.readme.io/d3444c0-Screenshot_2024-07-16_at_15.03.59.png" alt="Available Budibase blocks"><figcaption><p>Available blocks</p></figcaption></figure>

For more granular control, use the **Eject** button to edit individual block settings. This allows you to fine-tune elements like form fields within a Form Block.

<figure><img src="https://files.readme.io/4ce0ddf-Screenshot_2024-07-16_at_15.07.43.png" alt="Ejected table block resulting in a detailed component tree"><figcaption><p>Ejected Form Block resulting in a detailed component tree</p></figcaption></figure>

### Preview and Publish

During development you can test out your app. Click the `Preview` button in the top-right to open the app in a modal. The app preview will always open the screen selected within the builder.

<figure><img src="https://files.readme.io/db08598-Screenshot_2023-06-28_at_13.32.57.png" alt="Preview and Publish buttons"><figcaption><p>Preview and Publish buttons</p></figcaption></figure>

<figure><img src="https://files.readme.io/cfdbd7b-Screenshot_2024-07-16_at_15.10.31.png" alt="App preview showing a &#x27;Detail&#x27; side panel"><figcaption><p>App preview showing an Employees table</p></figcaption></figure>

Notice that navigation links were automatically added to the nav bar when we created the autogenerated screens.

To view the app with a different permission level, change the `View as basic user` option.

<figure><img src="https://files.readme.io/7b02fb9-Screenshot_2024-07-16_at_15.15.44.png" alt="A public user does not have permission to view the app by default"><figcaption><p>A public user does not have permission to view the app by default</p></figcaption></figure>

When you are happy with your app, click `Publish` to make your app live in production.

<figure><img src="https://files.readme.io/36c8f75-Screenshot_2024-07-16_at_15.16.43.png" alt="Publishing an app"><figcaption><p>Publishing an app</p></figcaption></figure>

<figure><img src="https://files.readme.io/8fc6c8f-Screenshot_2024-07-16_at_15.21.01.png" alt="App published!"><figcaption><p>Published app</p></figcaption></figure>

When an app is published, green text will show you when your app was last published. In addition you will have a few other options available:

| Name      | Description                                                             |
| --------- | ----------------------------------------------------------------------- |
| Unpublish | Remove your app entirely from production                                |
| Revert    | Sync your production app into dev (overwriting any changes)             |
| Publish   | Sync your dev app into production                                       |
| Embed     | Get the iframe code for Embedding your app                              |
| Open link | Click on the title of your app to open your production app in a new tab |

### Automate

Automations are not needed for all use-cases, however they offer powerful workflow options such as Cron jobs and Webhooks integrations.

More information can be found in the Automations page.

***

### Settings

The settings tab includes a variety of options for your app. These include:

* Automations
* Backups
* Embed
* Export/Import
* Name and URL
* Version

In addition you can `Delete app`. After confirmation, this will unpublish and **permanently delete your app**.
