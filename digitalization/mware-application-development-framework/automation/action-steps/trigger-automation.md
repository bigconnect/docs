# Trigger automation

As outlined on the [Triggers](https://docs.budibase.com/docs/trigger) page there are a variety of ways to trigger an automation.

In particular the [App action](https://docs.budibase.com/docs/app-action) trigger allows an End User to directly trigger an automation. It is also possible to call these _app action_ automations from another automation. This is done with the **Trigger an automation** step.

![](https://files.readme.io/cf613d7-Screenshot\_2024-02-23\_at\_14.32.05.png)

Select an _Automation_ (only **app action** automations will be available). Next you will see the fields from the target automation that must be filled out. In this case it is just the _employee\_id_.

<figure><img src="https://files.readme.io/c0fd788-Screenshot_2024-02-23_at_14.35.11.png" alt="App action trigger of the target automation"><figcaption><p>App action trigger of the target automation</p></figcaption></figure>

Optionally set the _Timeout (ms)_ if you want to make use of the response.

**Using the output**

There are a couple of useful [bindings](https://docs.budibase.com/docs/data-in-automations) that are provided by the trigger an automation action step.

<figure><img src="https://files.readme.io/0552f32-Screenshot_2024-02-23_at_15.03.08.png" alt="Selecting the trigger automation outputs"><figcaption><p>Selecting the trigger automation outputs</p></figcaption></figure>

<figure><img src="https://files.readme.io/759e045-Screenshot_2024-02-23_at_15.04.51.png" alt="Available bindings"><figcaption><p>Available bindings</p></figcaption></figure>

* **Success** - a _boolean_ field that indicates if the triggered automation passed or errored
* **Value** - the object representing the output of the target automation

### Tutorial: Generating onboarding tasks for new employees

In this tutorial we will use automations to generate onboarding tasks from a template table whenever a new employee is added.

#### Data

Create three tables.

| Table name                  | Columns                                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Employees**               | <p>first_name: <code>Text</code>,<br>last_name: <code>Text</code>,<br>hired_date: <code>Date</code></p> |
| **OnboardingTasks**         | date: `Date`                                                                                            |
| **OnboardingTaskTemplates** | <p>title: <code>Text</code>,<br>description: <code>Text</code></p>                                      |

With our tables created, we need to create Relationships between them as follows:

* One _Employee_ -> Many _OnboardingTasks_
* One _OnboardingTaskTemplate_ -> Many _OnboardingTask_

Finally create a _static_ Formula column in the **OnboardingTask** table. Set this value to the `Template Relationships` _title_ field:

<figure><img src="https://files.readme.io/97ae0d6-Screenshot_2024-02-23_at_15.25.01.png" alt=""><figcaption></figcaption></figure>

In the **Design** section, create two autogenerated screens for the **Employees** and **OnboardingTasks** tables.

#### Automation

The automation section is now where we are going to generate onboarding tasks from our templates whenever a new employee is created.

1. First create a new App action automation, and `Add field` _employee\_id_.
2. Add a Query Rows step and select the **OnboardingTaskTemplates** table

<figure><img src="https://files.readme.io/f270043-Screenshot_2024-02-23_at_15.32.52.png" alt="Get all the onboarding task templates"><figcaption><p>Get all the onboarding task templates</p></figcaption></figure>

3. Add a **Create Row** step for the **OnboardingTasks** table, and [Add Looping](https://docs.budibase.com/docs/looping).
   1. The _Input type_ should be `Array`, and the _Value_ should be the output of our templates query: `{{ steps.1.rows }}`
4. Now fill out the values for the **OnboardingTask** fields:
   1. _Date_: `return new Date()` _(JavaScript binding)_
   2. _Template_: `{{ loop.currentItem._id }}`
   3. _Employee_: `{{ trigger.fields.employee_id }}`

<figure><img src="https://files.readme.io/9109b7f-Screenshot_2024-02-23_at_15.40.54.png" alt=""><figcaption></figcaption></figure>

We now have an automation that will create onboarding tasks from our templates, but we still need to _trigger_ this automation. We will do this from a second automation:

5. Create a new automation with a **Row Created** trigger. Select the **Employees** table
6. Add a **Trigger an automation** action step. Select the first automation we created earlier, and provide the _employee\_id_ Binding: `{{ trigger.id }}`

<figure><img src="https://files.readme.io/eaf7779-Screenshot_2024-02-23_at_15.44.40.png" alt=""><figcaption></figcaption></figure>

Publish your app to test out the workflow!
