# OAuth 2 Scopes

In OAuth 2.0, applications are granted access to limited subsets of user data. These are called _scopes_ (not to be confused with Liferay scopes). You can create them in two ways:

* Administrators can create a Service Access Policy for the scope.
* Developers can create a JAX-RS endpoint. By default, the JAX-RS endpoint generates scopes based on the HTTP verbs it supports. A special annotation overrides this behavior and registers specific scopes.

### [Creating a Scope for a JSONWS Service](https://learn.liferay.com/web/guest/w/dxp/headless-delivery/using-oauth2/oauth2-scopes#creating-a-scope-for-a-jsonws-service) <a href="#creating-a-scope-for-a-jsonws-service" id="creating-a-scope-for-a-jsonws-service"></a>

The most common way to create a scope is to create a [Service Access Policy](https://learn.liferay.com/web/guest/w/dxp/installation-and-upgrades/securing-liferay/securing-web-services/setting-service-access-policies) prefixed with the name `OAUTH2_`. This naming convention causes the policy to appear in the OAuth application configuration screen as a scope.

For example, say the application needs access to a user’s profile information to retrieve the email address. To grant the application access to this,

1. Go to _Control Panel_ → _Security_ → _Service Access Policy_,
2.  Create a policy per the information below.

    | Field         | Value                                           |
    | ------------- | ----------------------------------------------- |
    | Name          | OAUTH2\_userprofile                             |
    | Enabled       | True                                            |
    | Default       | False                                           |
    | Title         | read your personal user data                    |
    | Service Class | `com.liferay.portal.kernel.service.UserService` |
    | Method Name   | `getCurrentUser`                                |

    ![A service access policy defines the scope for OAuth 2.0 applications.](https://resources.learn.liferay.com/images/dxp/latest/en/headless-delivery/using-oauth2/oauth2-scopes/images/01.png)

    Note that the policy is not a default policy, and that it grants access only to one method in the `UserService`. This is a JSONWS web service generated by Service Builder. You can view a list of all available services in your installation at this URL: `http://[host]:[port]/api/jsonws/`
3. Go to _Control Panel_ → _Security_ → _OAuth2 Administration_.
4.  Select _Fragment Renderer_.

    When you create a policy and prefix it with `OAUTH2_`, it appears in the _Scopes_ tab.

    ![Scopes named with the proper prefix appear in the Scopes tab of your application configuration.](https://resources.learn.liferay.com/images/dxp/latest/en/headless-delivery/using-oauth2/oauth2-scopes/images/02.png)
5. You can find the newly created scope under `PORTAL SERVICES` and save your application.

NOTE

There’s another scope called _read your personal user data_. This is one of the many out-of-the-box scopes that comes with Liferay.

### [Creating the Authorization Page](https://learn.liferay.com/web/guest/w/dxp/headless-delivery/using-oauth2/oauth2-scopes#creating-the-authorization-page) <a href="#creating-the-authorization-page" id="creating-the-authorization-page"></a>

This step is optional. Users need an interface to authorize access to their accounts, and one is provided automatically. If, however, you want to customize the page, you can create an authorization page in your Site.

1.  Open the _Global Menu_ (![Global Menu](https://resources.learn.liferay.com/images/dxp/latest/en/images/icon-applications-menu.png)), click the _Control Panel_ tab, and go to _Instance Settings_ → _Security_ → _OAuth 2_ → _Authorize Screen_.

    This screen displays the Authorize Screen URL field with this default value: `/?p_p_id=com_liferay_oauth2_provider_web_internal_portlet_OAuth2AuthorizePortlet&p_p_state=maximized`. This corresponds to an internal portlet.

    ![Configure the OAuth 2 Authorize Screen.](https://resources.learn.liferay.com/images/dxp/latest/en/headless-delivery/using-oauth2/oauth2-scopes/images/03.png)
2. Set the desired URL for the Authorize Screen (e.g., `/authorize`).
3. Navigate to the desired Site and open the _Site Menu_ (![Site Menu](https://resources.learn.liferay.com/images/dxp/latest/en/images/icon-product-menu.png)), expand _Site Builder_, and click _Pages_.
4.  Click the _Add_ button (![Add Button](https://resources.learn.liferay.com/images/dxp/latest/en/images/icon-add.png)) button and choose _Page_.

    NOTE

    For Liferay DXP 7.3 and earlier, create a Private Page. Only authenticated users can access Private Pages.
5. Choose the _Full Page Application_ type.
6. Give the page the same name you configured in step 2.
7. Turn the _Hidden from Navigation Menu Widget_ switch on. You don’t want this page showing up in your Site navigation.
8. On the page that appears next, verify the Friendly URL matches the URL you configured in step 2.
9. Under _Full Page Application_, choose _Application Authorization Request_.
10. Click _Save_.

Excellent! Users can use the default or the UI of your design to go through the authorization process. Now that you have the UI and you understand scopes, it’s time to make the authorization process happen in your application.
